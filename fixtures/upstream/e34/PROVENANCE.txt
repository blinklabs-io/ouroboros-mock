These are committed pinned Haskell-oracle fixtures, not an installed-node
replay. Import/integrity verification does not execute Haskell or claim a
new regeneration. Ordinary Go consumers need neither Haskell nor adjacent
workspaces. EmbeddedFixtures() exposes upstream/e34/... directly.
SHA256SUMS uses standard SHA-256 lines relative to this directory and covers
all imported files, their licenses and this provenance record.

Regeneration is explicit and requires the original Jormanager layout:
reference/cabal.project has a repository-root-relative packages path;
reference/verify.py derives ROOT from its original src/test/reference/
leaderlog location and reads src/test/resources/leaderlog. Restore these
files unchanged at those original paths in the named Jormanager checkout,
not in this flattened import directory. The verifier additionally requires
the pinned ledger source's libs/non-integral/reference C corpus and source,
cc/g++, GMP, and a built oracle. Full C goldens are not imported here.
From that original Jormanager root:
  cabal build --project-file=src/test/reference/leaderlog/cabal.project \
    jormanager-leaderlog-oracle
  cabal list-bin --project-file=src/test/reference/leaderlog/cabal.project \
    jormanager-leaderlog-oracle
Then run verify.py --check --ledger-source <pinned-ledger-source> \
  --oracle <built-executable> explicitly. Preserve the project/freeze and
index states; do not substitute an ideal numerical model or port output.

The artificial certified-natural endpoint M is arithmetic-only and is not
serializable into its N-bit VRF output. The low-level predicate's zero-stake
f=1 acceptance is not a pool registration or zero-pool policy claim.
Schedule overlay filtering is corpus replay policy, not this fixture
library's runtime eligibility API.
